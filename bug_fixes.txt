BUG #1: React SSR / Client Hydration Mismatch & Initial Persona State
- Location:
  * src/app/(app)/layout.tsx
  * src/components/layout/AppLayout.tsx
  * src/components/layout/Topbar.tsx
- Issue:
  The application suffered from React hydration mismatch errors on page load.
  The server rendered the default fallback persona (Rithwik / Learner) because
  app layout was a pure client component without initial SSR session resolution.
  When the client hydrated, the cookie or localStorage differed from SSR markup,
  causing React errors #418 / #423 / #425 and flickering UI.
- Fix:
  1. Converted src/app/(app)/layout.tsx into an async Server Component that fetches
     authenticated user metadata via getAuthenticatedUser() during SSR.
  2. Passed initialUser and initialRole as props down to AppLayout, Topbar, and
     Sidebar.
  3. Replaced client-only initial persona defaults in Topbar with getInitialPersona(initialUser, initialRole)
     to guarantee identical server markup and initial client DOM.

BUG #6: React Hydration Mismatches in Notifications & Client Storage Components
- Location:
  * src/app/(app)/notifications/page.tsx
  * src/app/(app)/notifications/NotificationsClient.tsx
  * src/components/dashboard/trainer/TrainerReviewTriageCard.tsx
  * src/components/skill-gap/RemediationRoadmap.tsx
  * src/app/(app)/review-queue/page.tsx
- Issue:

     the client read document.cookie during initial hydration, causing a React hydration
     mismatch exception (#418 / #423) when viewing as admin or trainer.
  2. In TrainerReviewTriageCard, RemediationRoadmap, and ReviewQueuePage, useState

  3. Refactored TrainerReviewTriageCard, RemediationRoadmap, and ReviewQueuePage to utilize
     React's useSyncExternalStore with snapshot reference caching and custom storage update
     events, completely eliminating all hydration mismatches and cascading render warnings.

BUG #8: Profile Button and Logged-In User Name Mismatch
- Location:
  * src/components/layout/Topbar.tsx
  * src/components/layout/AppLayout.tsx
  * src/components/layout/Sidebar.tsx
  * src/proxy.ts
  * src/lib/auth.ts
  * src/app/api/sso/demo-persona/route.ts
- Issue:
  The dashboard and page greeted the authenticated user (e.g., Sunita Devi, Field
  Investigator), but the profile button in the top navigation bar either reverted
  to "Rithwik" or failed to match the active user session.
  Root cause: In /api/sso/demo-persona, Next.js response.cookies.set() automatically
  URL-encodes values. The route handler was passing encodeURIComponent(JSON.stringify(userObj)),
  resulting in double URL encoding (%257B...). When client or server code called
  JSON.parse(decodeURIComponent(cookie)), %257B decoded to %7B instead of {, causing
  a JSON syntax error and falling back to persona 0 (Rithwik). Additionally, Topbar
  and Sidebar maintained local state that lagged behind or diverged from the authenticated
  currentUser resolved by AppLayout.
- Fix:
  1. Stopped double URL encoding in src/app/api/sso/demo-persona/route.ts (both GET and POST).
  2. Implemented safeDecodeCookie in Topbar.tsx, AppLayout.tsx, Sidebar.tsx, proxy.ts,
     and auth.ts to iteratively decode multi-encoded cookie strings before JSON parsing.
  3. Threaded the resolved currentUser prop from AppLayout directly to Topbar and Sidebar.
  4. Derived activePersona directly from currentUser in Topbar.tsx, guaranteeing immediate,
     reactive, and synchronous display of the logged-in user's name, cadre, and designation
     in the profile button across all roles.
